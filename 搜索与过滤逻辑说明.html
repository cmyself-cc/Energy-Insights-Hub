Energy Insights Hub 搜索与过滤逻辑说明

生成时间：2026-07-24 · 基于当前代码版本整理

一、整体流程概览

Tracker 每次运行时，按以下顺序处理每个活跃来源：

1. 抓取源内容 → 2. URL/标题去重 → 3. 关键词门控过滤 → 4. 模糊去重 → 5. 预过滤（时间/数量） → 6. LLM 语义处理 → 7. 后过滤与入库

其中只有第 1 步（部分来源）和第 6 步会调用外部 API/LLM，其余均为本地算法。

二、数据来源与抓取逻辑

当前数据库中活跃来源：api × 23、website × 5、wechat_mcp × 1。

来源类型 抓取方式 外部依赖 说明
rss 本地算法 无 使用 rss-parser 解析 RSS 订阅，取前 N 条，提取标题、摘要、链接、发布时间。
website 本地算法 目标网站 HTTP 请求 三级 fallback：① 自动发现 RSS 并解析；② 读取 sitemap.xml；③ 解析首页 HTML 列表并抓取详情页。使用随机 User-Agent、Cheerio 提取正文。
wechat_mcp 外部 API MCP SSE 服务器 通过 SSE 长连接连接本地/远程 MCP 服务器，调用 list_wechat_feeds、get_feed_articles、get_article_fulltext 获取公众号文章。
api（Tavily） 外部 API Tavily Search API 用 Tavily 搜索指定 domain/query，返回结果后过滤掉首页/分类页/PDF，保留新闻类文章。
注意： 所有抓取的文章对象统一为 { title, summary, url, publishDate, rawContent, source }。其中 rawContent 是 LLM 后续处理的主要输入。

三、关键词门控过滤（Keyword Gate）

文件：server/services/keywordGate.js

匹配范围：title + summary（不读 rawContent，减少计算）。

3.1 三层递进规则

每个监控类型（competitor / policy / tech）独立配置三层关键词：

  • enterprise（企业/主体关键词）：该类型关注的企业、机构或技术主体。
  • include_keyword（包含关键词）：事件性质关键词，如合作、投资、收购、并购、政策、技术突破等。
  • exclude_keyword（排除关键词）：只要出现就整体排除该文章的关键词，如指数、股价、涨停、住宅。

3.2 匹配逻辑（当前已改为 AND）

对所有文章： 1. 先检查全局 excludeKeywords（tracker_settings.exclude_keywords），命中则丢弃。 2. 对每个 purpose： if exclude_keyword 命中 → 该 purpose 不匹配 if enterprise 命中 AND include_keyword 命中 → 该 purpose 匹配 3. 收集所有匹配的 purpose 列表（matchedPurposes）。 4. 如果没有任何 purpose 匹配 → 丢弃。

关键变更： 现在所有监控类型都必须同时满足 enterprise AND include_keyword，不是“或”关系。例如竞争监控需要同时提到某家企业 并且 出现投资/合作/收购等词。

四、去重机制

文件：server/services/dedup.js

本地算法 两层去重：

  1. URL 精确去重：与本次 batch 内及数据库近 N 天的 URL 比对。
  2. 标题模糊去重：使用 2-gram Dice 系数，阈值默认 0.85。标题相似度 ≥ 0.85 视为重复。

五、预过滤（Pre-filter）

文件：server/services/trackerRules.js

本地算法 两步：

  1. 时间过滤：只保留 publishDate 在 lookbackHours（默认 24 小时）内的文章。30 天模式需手动改为 720。
  2. 每来源数量限制：每个来源最多保留 max_per_source 篇（默认 3），按时间倒序。

六、LLM 语义处理

文件：server/services/llmProcessor.js

外部 LLM API 这是唯一调用大语言模型的地方。

6.1 LLM 输入

  • API 地址：由环境变量 LLM_BASE_URL 决定（当前为 Siliconflow）。
  • 模型：由 LLM_MODEL 决定。
  • 请求内容：文章的 title + rawContent（LLM 读原文，不只是摘要）。

6.2 LLM 输出字段

字段作用
title10-20 字中文精炼标题，剔除来源名、日期、作者。
summary150 字以内信息密集摘要，清理噪音。
keywords恰好 3 个具体可搜索关键词（企业/技术/事件/政策）。
purposes监控类型数组：competitor / policy / tech，不符合则返回 []，文章丢弃。
categories1-3 个业务/事件分类，至少包含一个业务分类。
china_relevance是否与中国强相关（中国发生/中国企业/中国政策/中国市场），false 则丢弃。

6.3 并发与限流

  • 每次批量处理 2 篇文章（BATCH_SIZE = 2）。
  • 每批之间 sleep 2 秒。
  • 单条 LLM 请求超时 60 秒。
为什么最近 0 张 insight？
最近一次运行：26 个来源成功抓取，3 个失败。关键词门控能通过的文章是存在的（微信公众号 15/20、财联社 6/10、腾讯新闻 7/10 等），但 LLM 处理阶段大量超时/被限流（This operation was aborted），导致全部被丢弃。

七、后过滤与入库

文件：server/services/tracker.js、server/services/trackerRules.js

本地算法 LLM 返回后执行以下过滤：

  1. 去掉 LLM 处理失败的文章（llmFailed = true）。
  2. 去掉 chinaRelevance = false 的文章。
  3. 去掉 purposes 为空的文章。
  4. 按用户启用的业务分类（business_categories.active=1）再过滤。
  5. 去掉无标题的文章；超长正文（>200 字）已被你要求丢弃（代码中有体现）。

最终存入 insights 表，字段包括来源、标题、摘要、URL、发布时间、来源类型、业务域、企业类型、实体、关键词、分类、监控类型等。
